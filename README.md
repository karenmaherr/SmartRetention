# Customer Churn Prediction and Retention Targeting

A machine learning pipeline that gives every telecom customer a **probability of leaving**, then ranks customers by **how much money that departure would cost**. The company uses the ranking to send retention offers only to the customers who matter most.

---

## The idea

Most retention budgets are wasted in one of two ways: a discount for everyone, or nothing until the customer calls to cancel. This project does something narrower.

1. Predict the chance that each customer churns.
2. Multiply it by what the customer is worth to get an **Expected Loss Score**.
3. Make retention offers to the **top 15% to 25%** of that ranking, and nobody else.

The offers are aimed at people who are likely to leave and worth keeping, so the budget stays small. Customers who feel looked after also tend to recommend the company, which can bring in new customers on top of the ones retained.

```
Client.csv + Record.csv
        |
   merge on Customer_ID
        |
   feature engineering 
        |
   LightGBM + XGBoost + CatBoost, 5-fold CV
        |
   weighted blend  ->  churn_probability
        |
   Expected_Loss_Score = churn_probability x totrev
        |
   FinalDataframe.csv  (sorted, highest loss first)
```

## Input data

| File | Columns | Content |
|---|---|---|
| `Client.csv` | 50 | Demographic and personal details: income, area, marital status, number of phones, credit class and similar |
| `Record.csv` | 51 | Usage and plan details: average minutes, revenue, dropped calls, handset age, customer care calls, and the `churn` target |

The two files are joined on `Customer_ID` (inner join), giving one row per customer.

> The data files are not included in this repository.

## Method

### Preparation
- Dropped `recv_sms_Mean`, `iwylis_vce_Mean`, `ownrent` and `Customer_ID` (as a feature).
- Categorical columns are encoded with an ordinal encoder. CatBoost also uses its native categorical handling.
- Missing values are left as missing, and the number of missing fields per customer is added as a feature.

### Feature engineering
About 70 engineered features in these groups:

| Group | Examples |
|---|---|
| Trends | Recent versus earlier minutes, quantity and revenue, relative change |
| Pricing and mix | Revenue per minute, overage, data and roaming shares |
| Network quality | Completed, dropped, blocked and unanswered call rates, bad events |
| Service contact | Customer care call rates, value added service adoption |
| Device and tenure | Handset age flags, phone changes per year, tenure cycle |
| Account structure | Ratios between lines on the account |
| Credit and location | Credit class grade, frequency encoding of area, credit class, social group and ethnicity |
| Peer comparison | Deviation from area and credit-class means, percentile ranks |
| Data quality | Count of missing values |

Features with zero importance in a first LightGBM fit are removed.

### Models

| Model | Main settings |
|---|---|
| LightGBM | 1500 trees, learning rate 0.04, 20 leaves, min 100 samples per leaf, column sample 0.5, row sample 0.8, L2 = 7 |
| XGBoost | 1100 trees, learning rate 0.04, depth 5, L2 = 6, histogram method |
| CatBoost | 2200 iterations, learning rate 0.04, depth 5, native categorical features |

Final probability = (4 x LightGBM + 2 x XGBoost + 1 x CatBoost) / 7

### Validation
5-fold stratified cross-validation with out-of-fold predictions, so every customer is scored by a model that never saw them.

| Metric | Value |
|---|---|
| Out-of-fold ROC-AUC (blend) | **0.7062** |

This is a moderate score. It is good for ranking customers and focusing a budget, and it is not meant for judging whether one particular customer will leave.

## Output

`FinalDataframe.csv`, one row per customer, sorted by `Expected_Loss_Score` from highest to lowest.

| Column | Meaning |
|---|---|
| `Customer_ID` | Same ID as in the input files |
| `churn_probability` | Blended probability that the customer leaves (0 to 1) |
| `Expected_Loss_Score` | `churn_probability x totrev`, the money at risk |

### How to use it
- Top 15%: priority group, strongest offer.
- Next 10% (15% to 25%): lighter offer.
- Everyone else: no offer.

Keep a small random control group that gets no offer. It is the only reliable way to measure what the offers actually did.
